# Monolith Constraint Violation — Issue #1

## Conflict

Issue #1 ("User Requests Management") from GitLab project `root/artifacts` (#5) violates the "one use case per document" architectural principle.

## Evidence

**Signal 1: Multiple Actor Roles**
- Company Super Admin (submits requests, views own requests)
- Bank Reviewer (approves/rejects all requests)
- System (automated user identity generation)

Three distinct roles with independent goals → **signal detected**

**Signal 2: Multiple Command Triggers**
- FR-001: Submit User Request
- FR-002: View Request Tracking List
- FR-003: Approve/Reject Request
- FR-004: Generate User Identity & Send Invitation

Four distinct functional requirements without shared precondition → **signal detected**

**Signal 3: Independent Outcome Sets**
- Request submission → request created (pending status)
- Request tracking → list displayed (decoupled from submission)
- Request approval → status updated + user identity generation triggered
- User identity → user created + email sent (orthogonal to request management)

Multiple success paths with no mutual dependency → **signal detected**

**Signal 4: Disjoint State Machines**
- UserRequest aggregate: pending → approved/rejected
- User aggregate: (created by system, orthogonal to request)

Two independent entity lifecycles → **signal detected**

## Classification

**Signals present:** 4 (threshold: 2+)  
**Conflict class:** `rule_violation`  
**Blocking:** YES — INGEST and ABSORB cannot proceed until resolved
